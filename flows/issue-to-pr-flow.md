# Issue To PR Flow

Use when a project manages meaningful development through GitHub issues.

1. Select one ready issue according to the project's priority labels.
2. Read issue body, comments, acceptance criteria, and linked docs.
3. Produce a task card:
   - Issue.
   - Goal.
   - Scope.
   - Non-goals.
   - Acceptance criteria.
   - Risk level.
   - Reviewer decision.
   - Branch or worktree plan.
4. Create an isolated branch or worktree if the task is more than a tiny fix.
5. Implement only the issue scope.
6. Validate.
7. Create a PR with done state, risk, verification, and human acceptance guide.
8. Update the issue according to project rules.
9. Stop unless the user or project explicitly allows continuing.
